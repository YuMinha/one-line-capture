# spec.md — 한 줄 캡처 앱

> 최종 수정: 2026-09-30 / 상태: v1 스코프 확정 + 게스트 모드 추가 (tasks.md G1~G5)

## 1. 한 문장 정의

**입력창에 한 줄만 던지면, 앱이 지출·할일·링크로 알아서 분류해서 저장해주는 개인 기록 앱.**

기존 앱들은 "무엇을 기록할지"를 먼저 고르게 한다. 지출은 가계부 앱, 할일은 투두 앱,
링크는 북마크. 그 선택 자체가 마찰이라서 결국 아무 데도 안 남는다.
이 앱은 순서를 뒤집는다 — 일단 던지고, 분류는 앱이 한다.

## 2. 타겟

**1순위: 나 (v1의 유일한 사용자).**

이건 겸손이 아니라 설계 원칙이다. v1의 성공 기준은 "사람들이 좋아하는가"가 아니라
**"내가 4주 뒤에도 매일 쓰고 있는가"** 하나다. 내가 안 쓰는 앱은 남도 안 쓴다.

**구경하는 사람 (게스트, 2026-09-30 추가).** 친구에게 보여주려면 친구도 직접 던져봐야 한다.
주소를 열면 **가입 없이 그 기기 전용 계정이 자동으로 생긴다.** 내 기록은 보이지 않고, 친구 기록도 나에게 안 보인다.
이건 "남이 가입해서 쓰는 버전"(§5)이 아니다 — 계정을 기기 밖으로 가져갈 방법이 없는, 체험용 칸막이다.

2순위(v2 이후): 메모 앱에 한 줄씩 쌓아두고 정리 못 하는 사람, 가계부를 3일 쓰다 마는 사람.

### 안티 타겟 (이 사람들을 위해 만들지 않는다)

- 상세한 가계부를 원하는 사람 — 카테고리·예산·카드 연동을 기대하면 실망한다
- 팀 협업을 원하는 사람 — 이건 끝까지 1인용이다
- 완벽한 자동 분류를 기대하는 사람 — 규칙 기반은 틀린다. 대신 고치기 쉽게 만든다

## 3. 핵심 사용 흐름

```
입력창에 "점심 9000원" 입력
        ↓ (0.3초, 화면 전환 없음)
지출로 저장됨 · 금액 9,000원 · 오늘 날짜
        ↓
목록에서 잘못 분류된 게 보이면 탭해서 타입 변경
```

**전체 앱에서 가장 중요한 문장: 입력에서 저장까지 탭이 한 번(엔터)이어야 한다.**
확인 다이얼로그, 카테고리 선택, 저장 버튼 — 전부 이 원칙을 깨므로 v1에 넣지 않는다.

### 분류 예시

| 입력 | 분류 | 뽑아내는 값 |
|---|---|---|
| `점심 9000원` | 지출 | 금액 9000, 항목 "점심", 날짜 오늘 |
| `스벅 5,500원` | 지출 | 금액 5500, 항목 "스벅" |
| `택시 1만원` | 지출 | 금액 10000, 항목 "택시" |
| `내일 3시 과제 제출` | 할일 | 제목 "과제 제출", 마감 내일 15:00 |
| `9/2 팀플 발표` | 할일 | 제목 "팀플 발표", 마감 9월 2일 |
| `https://... 스프링 정리글` | 링크 | URL, 메모 "스프링 정리글" |
| `우산 챙기기` | 할일 | 제목 "우산 챙기기", 마감 없음 |

마지막 줄이 중요하다. **아무 규칙에도 안 걸리면 할일로 떨어진다.**
"미분류함"을 따로 두지 않는 이유는 §6에 있다.

## 4. v1 스코프 — 4주, "내가 매일 쓰는 버전"

### 화면 3개 (이 이상 늘리지 않는다)

1. **입력** — 텍스트 한 줄 + 방금 저장된 것 3개 미리보기
2. **목록** — 전체 / 지출 / 할일 / 링크 탭, 항목 탭하면 수정·타입변경·삭제
3. **요약** — 이번 달 지출 총액, 건수, 일별 합계 (숫자와 표만. 차트 없음)

(토큰 입력 화면 `#/token`은 여기 세지 않는다. 처음 접속하면 토큰이 자동 발급되므로 평소엔 안 뜨고,
주인이 새 기기에 자기 토큰을 넣을 때만 쓰는 뒷문이다.)

### 기능

- [x] 한 줄 입력 → 규칙 기반 자동 분류 후 저장
- [x] 타입별 목록 조회 (페이징)
- [x] 잘못된 분류 수정 (타입 변경 + 상세 필드 수정)
- [x] 항목 삭제
- [x] 할일 완료 체크
- [x] 월별 지출 요약 (총액 / 건수 / 일별)
- [x] PWA — 홈 화면에 추가하면 앱처럼 뜸
- [x] 고정 API 토큰 1개로 내 데이터 보호
- [x] 게스트 모드 — 처음 접속한 기기에 토큰 자동 발급, 사용자별 데이터 분리 (주인 토큰은 여전히 `API_TOKEN`)
- [x] public GitHub 레포 — docker-compose, `.env.example`, README 로컬 실행법
- [x] VPS에 배포해서 내 폰에서 접속

### v1 완료 기준 (체크리스트)

이 5개가 전부 참이면 v1은 끝난 것이다. 아니면 아직 안 끝난 것이다.

1. 내 폰 홈 화면 아이콘에서 열린다
2. 처음 보는 사람이 README만 보고 `docker compose up`으로 로컬 실행에 성공한다
3. 파서 테스트가 30개 이상 있고 전부 통과한다
4. 7일 연속으로 실제 기록을 남겼다
5. API 주소·DB 비밀번호·API 토큰이 코드에 하드코딩되어 있지 않다

## 5. v2 이후로 미루는 것

미루는 것이지 안 하는 게 아니다. **다만 v1이 §4의 완료 기준 5개를 다 채우기 전에는
아래 중 어느 것도 시작하지 않는다.**

| 항목 | 왜 지금은 아닌가 |
|---|---|
| ~~남이 가입해서 쓰는 버전~~ → **앞당김 (2026-09-30, tasks.md A1~A6)** | 아래 "앞당긴 이유" 참고. 비밀번호 찾기(메일 발송)만 여전히 미룬다 |
| 비밀번호 찾기 | 메일 발송 = 새 의존성 + SMTP 계정 + 이메일 인증. 로그인과 별개 주제다 |
| 소셜 로그인 (카카오/구글) | OAuth 리다이렉트 설정만으로 며칠. 사용자가 나 하나면 얻는 게 없다 |
| 알림 · 푸시 | Web Push는 VAPID 키·서비스워커·권한 흐름이 별도 주제다. 4주에 안 들어간다 |
| 통계 차트 | 차트 라이브러리 도입 = 프론트 학습량 증가. 숫자와 표로도 "이번 달 얼마 썼지"는 답이 나온다 |
| LLM 하이브리드 분류 | 규칙 기반을 먼저 끝까지 짜봐야 LLM이 뭘 대신해주는지 알 수 있다. 순서가 반대면 배우는 게 없다 |
| 셀프호스팅 문서화 | 남이 쓸 때 필요하다. v1은 내가 내 서버에 올리는 것까지 |
| 커스텀 서버 연결 UI | 위와 같은 이유 |

### 앞당긴 이유 — 로그인·기기 연결 (2026-09-30)

§8의 질문에 대한 답: **완료 기준 중 남은 건 "폰 설치 확인"과 "7일 연속 기록"이다.** 7일 기록은 날짜가
흘러야 채워지는 것이라, 매일 쓰면서 그 사이에 만들면 늦어지지 않는다. 쓰는 걸 멈추는 순간 늦어진다.

넣을 값어치: 목표가 "폰에서 급할 때 던지고 PC에서 이어서 보는 것"이라, 기기 간 연결이 없으면 앱의 쓰임새가 반쪽이다.
게스트 모드로 `user_id`가 이미 들어와 있어서 "게스트 계정에 로그인 수단 붙이기"로 이어진다.

- 아이디·비밀번호·이메일로 가입 (지금 게스트 계정에 붙인다 — 기록 유지)
- 기기 연결 코드: 로그인된 기기에서 받은 8자리 코드를 새 기기에 넣으면 비밀번호 없이 연결
- 기기별 로그아웃

## 6. 안 만들 것 (v2에도 안 만든다)

미루는 것과 다르다. **이건 이 앱의 정체성을 지키기 위해 거절하는 목록이다.**

- **미분류함 / 인박스** — 분류 못 한 걸 쌓아두는 공간은 반드시 쓰레기통이 된다.
  "나중에 정리하자"가 쌓이면 앱을 안 열게 된다. 애매하면 할일로 떨어뜨리고, 틀렸으면 목록에서 고친다.
- **저장 전 확인 화면** — §3의 원칙을 정면으로 깬다. 자동 분류가 틀리는 비용보다 매번 탭 하나가 더 비싸다.
- **폴더 / 태그 / 중첩 구조** — 정리 비용이 기록 비용보다 커지는 순간 앱은 죽는다. 타입 3개가 전부다.
- **카드·계좌 연동** — 스크래핑은 유지보수 지옥이고, 애초에 이 앱은 "손으로 던지는 한 줄"이 본질이다.
- **리치 에디터 / 첨부파일 / 이미지** — 한 줄 캡처 앱이다. 길게 쓰고 싶으면 노션을 쓰면 된다.
- **여러 기기 실시간 동기화** — 서버가 하나이므로 자연히 동기화된다. 오프라인 편집 병합은 v1에서 다루지 않는다
  (PWA는 "설치 가능"까지만, 오프라인 쓰기 큐는 넣지 않는다).
- ~~**네이티브 앱**~~ → **§9에서 허용으로 바뀜 (2026-10-09).** PWA로는 잠금화면 입력과 PC 전역 단축키를 만들 수 없다.

## 7. 알려진 한계 (v1이 못 하는 것을 미리 인정하기)

- 규칙 기반 파서는 **처음 보는 표현을 못 알아본다.** "밥값 만 원 정도?" 같은 건 할일로 떨어진다.
  → 대응: 고치기가 쉬우면 된다. 목록에서 타입 변경 2탭.
- **금액은 원화 정수만** 다룬다. 외화·소수점은 없다.
- 지출 날짜는 **입력한 날 기준**이다. "어제 점심 9000원"의 날짜 파싱은 v1 범위 밖 (규칙 추가로 나중에 확장 가능).
- 주인 토큰은 **새면 재발급이 수동**이다 (`.env`의 `API_TOKEN`을 바꾸고 api 재시작).
- 게스트 기록은 **그 브라우저에 저장된 토큰이 유일한 열쇠**다. 브라우저 데이터를 지우면 다시 못 연다.
- 게스트 발급에 **횟수 제한이 없다.** 사용자가 친구 몇 명인 동안은 감수한다.
- **비밀번호를 잊으면 복구할 수 없다.** 로그인된 기기가 하나라도 남아 있으면 연결 코드로 새 기기를 붙일 수는 있다.
- 게스트로 쓰던 기기에서 로그인하면 그 기기의 **게스트 기록은 계정에 합쳐지지 않는다.** (가입을 먼저 하면 유지된다)

스코프를 늘리고 싶어질 때가 반드시 온다. 그때 이 질문에 답하고 나서 고친다:

답이 "안 늦어진다"면 대체로 착각이다.

## 9. 목표 전환 — 학습에서 출시로 (2026-10-09)

**왜:** 웹 v1은 기능이 다 들어갔고 남은 완료 기준(폰 설치 확인, 7일 연속 기록)은 쓰면서 채워진다.
이제 배우는 것보다 **실제로 남이 설치해서 쓰는 단계까지 내보내는 경험**이 더 값지다.
그래서 §5의 "v1 완료 전엔 v2 금지"와 §6의 "네이티브 앱 금지"를 아래 범위에 한해 푼다.

**만드는 것 (이 순서로):**

1. **안드로이드 앱** — 홈 화면 위젯과 잠금화면에서 바로 한 줄 입력. 연결 코드로 기존 계정에 붙는다
   - **홈 화면 위젯**: 입력칸 + 방금 저장한 3개. 위젯 안에서는 글자를 칠 수 없어(안드로이드 제약) 누르면 입력창이 뜬다.
     잠금화면 위젯을 허용하는 기기에서는 잠금화면에도 올린다
   - 고정 알림의 "답장" 입력칸 — 대부분의 폰은 잠금화면에 남의 위젯을 못 올리므로 잠금화면 입력은 이게 맡는다
   - 빠른 설정 타일 → 한 줄 입력창
   - 앱 화면: 연결 코드 입력, 한 줄 입력, 방금 저장된 3개. **목록·요약은 웹을 연다** (화면을 두 벌 만들지 않는다)
2. **윈도우 메모칸** — 작업 표시줄 바로 위에 늘 떠 있는 한 줄 입력칸. 끌어서 옮기면 자리를 기억한다.
   어디서든 단축키(Ctrl+Shift+Space)를 누르면 이 칸으로 커서가 온다. 결과는 칸 안에 잠깐 보인다.
   윈도우 11은 작업 표시줄 **안**에 남의 칸을 넣을 수 없어서(디스크밴드 폐지) 그 **바로 위**에 붙인다
3. **배포 1단계: 직접 배포** — APK·exe를 GitHub Releases에 올리고 나와 지인이 설치
4. **배포 2단계: 공개** — 플레이 스토어 등록, 웹을 누구나 가입하는 서비스로 공개
   (개인정보처리방침·이용약관, 게스트 발급 횟수 제한이 먼저다)
5. **아이폰** — 안드로이드 출시 뒤. 먼저 iOS 단축어로 잠금화면 입력을 만들고, 앱은 그다음에 판단

**여전히 안 만드는 것:** §6의 나머지 전부. 앱에도 미분류함·저장 전 확인 화면·태그는 없다.
앱은 **입력 전용**이다. 분류 수정·목록·요약은 웹이 한다.
